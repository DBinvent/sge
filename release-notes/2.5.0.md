# Schema Guard Enterprise 2.5.0

2026-11-22. The command `sge`, the crate `schema_guard`. Needs schema_guard_tokio 2.5.0.

## New

- **Row access with a schema file.** A table's `security` in a schema YAML - who reaches which
  of its rows, by department and by level (schema_guard_tokio 2.5.0, "Row access") - is deployed
  with the file when the migration options say a mode: `security=lsr` or `security=rls` in
  `sg_migration`, any case.

  ```yaml
  - table:
      tableName: docs
      security:
        schemaPath:
          dml: [app.docs.project_id, app.projects.dept]
          sal: [app.docs.project_id, app.projects.sal]
  ```

  - `security=rls`: PostgreSQL's row-level security is enabled and forced on each declared
    table, with a policy per action.
  - `security=lsr`: the tables are registered for ytproxy's SQL rewrite, and no policy is made.
    sge reads several schema files, so a path may lead to a table of another file: deploy the
    file that defines an attribute before the files that reach it, or say the `alias`.
  - Not said, or `off`: nothing of a table's `security` is deployed. A word that is no mode is
    taken as off, and said in the log.
- A snapshot of a database writes back the declarations it holds.
